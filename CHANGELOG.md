# Changelog

## 0.2

Совместимость с PHP 8 и исправление ошибок. Схема БД и имена свойств не менялись —
обновление ставится поверх существующей установки.

### Критические (модуль не работал на PHP 8.0+)

- `hvac::CreateDevice()` вызывал нестатический `model()` статически →
  `Error: Non-static method hvac::model() cannot be called statically`.
  Это фатальная ошибка на любой операции с устройством. `model()` и `pair()` сделаны
  статическими. (`hvac.class.php`)
- `dev_hvac::table_data_set()` вызывал `count()` на результате `SQLSelectOne()`,
  который возвращает `NULL`, если строк нет → `TypeError: count(): Argument #1
  must be of type Countable|array, null given` при первом же опросе нового
  устройства. (`dev_hvac.class.php`)
- `hvac::byte2array()` вызывал `unpack()` на `array()`, который `send_packet()`
  возвращает при любой ошибке связи → `TypeError` вместо «устройство недоступно».
- `Gree::get_status()` вызывал `get_object_vars()` на `NULL`, если устройство не
  ответило → `TypeError`.
- `DiscoverGREE()` статически вызывал нестатический `pair()` → фатальная ошибка при
  сканировании сети.

### Ошибки протокола

- Пакет `bind` содержал `cid` и `tcid`, поменянные местами. Правильно `cid: "app"`,
  `tcid: <MAC устройства>` (сверено с эталонными реализациями gree-remote и greeclimate).
- Контрольная сумма C&H считалась как `intval(substr(dechex($sum), 1), 16)`. Это
  равно `$sum % 256` только при `0x100 <= $sum <= 0xFFF`; вне диапазона результат
  неверен. Заменено на `$sum & 0xFF`.
- `hvac::mac()` формировал MAC через `sprintf('%02x', '2c')`, то есть приводил
  hex-строку к числу: `50:2c:c6:00:11:22` превращался в `32:02:00:00:0b:16`. MAC
  теперь нормализуется в конструкторе.
- `Gree::get_mac()` читал `$this->mac[5]`…`[0]` при массиве из одного элемента —
  пять warning-ов на каждый пакет.
- Расшифровка Gree не учитывала, что устройства отдают пакет с нестандартным
  дополнением. Добавлен повтор с `OPENSSL_ZERO_PADDING` и обрезка по последней `}`,
  как в эталонных клиентах.
- Команды Gree рассылались широковещательно; ответ мог прийти от другого
  кондиционера. Теперь unicast на адрес устройства с широковещательным резервом.
- `send_gree_packet()` не закрывал сокет на ветке неуспеха.
- Не проверялись результаты `socket_connect()`, `fsockopen()`, `socket_sendto()`.
- `CH::set_fan_speed()` при неизвестном режиме использовал неинициализированную
  переменную `$result_mode`.

### Поддержка нового оборудования

- Добавлен протокол Gree v2 (AES-128-GCM). Версия определяется автоматически при
  сканировании и при привязке; переключатель есть в карточке устройства.
  Новое поле `dev_hvac_devices.ENCRYPTION` добавляется автоматически.
- Добавлены команды Gree: `fan_directionh` (SwingLfRig), `turbo`, `air`, `blow`,
  `stht`; для C&H — `eco`.
- Сканирование Gree теперь читает имя устройства из ответа (раньше поле имени
  оставалось пустым).

### Схема БД

- `dev_hvac_commands.VALUE` объявлялся как `TEXT NOT NULL DEFAULT ''`. MySQL
  запрещает литеральное значение по умолчанию для TEXT (ошибка 1101), поэтому
  колонка не создавалась. Объявлено как `text` без DEFAULT, по соглашению ядра.
- Добавлены индексы по `DEVICE_ID` и `LINKED_OBJECT`.

### Интерфейс и логика

- Опрос устройства вызывал `sg()` без исключения самого модуля из цепочки
  linked-modules: прочитанное с кондиционера значение тут же отправлялось обратно на
  кондиционер. Теперь `sg(..., array('dev_hvac' => 1))`.
- Добавление свойства (`title_new`) выполнялось внутри цикла по существующим
  свойствам: при N свойствах создавалось N копий, при нуле — ни одной. Перенесено
  из цикла; в шаблон добавлено поле ввода, которого не было.
- `LINKED_METHOD` был в таблице и в форме, но нигде не считывался и не сохранялся.
- `$old_linked_object` присваивался после перезаписи значения, поэтому
  `removeLinkedProperty()` никогда не вызывался — старые связи объектов не
  освобождались. Освобождение добавлено также при удалении устройства и свойства.
- SQL-инъекции: `$id`, `$chtime`, `$prop` подставлялись в запросы напрямую из
  GET/POST (ядро регистрирует параметры запроса как глобальные переменные).
  Добавлены приведение к `int` и `DBSafe()`.
- `!$_GET['data_source']` без `isset()` → warning на PHP 8; заменено на `empty()`.
- `$this->owner->name` без проверки на существование объекта.
- Отладочная строка `$current .= "in if $res[0]['ID']"` и мёртвая ветка, зависящая
  от несуществующего ключа `ID`, удалены из сканирования.
- Функция `Scan()` объявлялась в подключаемом файле без защиты от повторного
  объявления и занимала слишком общее имя. Переименована в `dev_hvac_scan()` и
  защищена `function_exists()`.
- Ключ устройства Gree передавался в ссылке «добавить» без кодирования, хотя может
  содержать `& + # % =`. Передаётся в base64url.
- В шаблоне `action_admin.html` вкладка «Данные» была написана как
  `&#060#LANG_DATA#&#062` и выводилась как текст `<#LANG_DATA#>`. Удалены
  подключения четырёх шаблонов, которых нет в репозитории.
- Исправлена незакрытая разметка в `dev_hvac_devices_edit_data.html` и лишний
  `</a>` в `hvac_devices_scan.html`. В результатах сканирования отмечаются уже
  добавленные устройства.
- Цикл `cycle_dev_hvac.php` считал итерации через неинициализированные переменные
  `$s5`, `$s20`, `$m10` и сбивался, если опрос длился дольше секунды. Переписан на
  расписание по времени; мёртвый код `$latest_check` удалён; ошибки опроса больше
  не роняют цикл.
- Конструктор в стиле PHP 4 (`function dev_hvac()`) заменён на `__construct()`;
  свойства модуля объявлены явно (PHP 8.2 объявляет динамические свойства
  устаревшими).
